# FPGA 以太网视频上位机

双击 **FPGA_Ethernet_Host.exe** 或 **启动上位机.cmd**。视频接收不依赖电脑另装 Python；“Python人体模型对照”是可选功能，使用已有的 yolo 环境和人体模型工程。

## 接线与开始接收

1. FPGA 网口用网线连接电脑有线网口，FPGA 保持当前已能运行人体 NPU 的配置。
2. 电脑有线网卡 IPv4 设为 `192.168.137.1`，掩码 `255.255.255.0`。本程序不会自动修改网卡；这台电脑检查时已经有该地址。
3. 软件默认监听 `0.0.0.0:6001`，限定来源 `192.168.137.2:6002`，点击“开始监听”。`0.0.0.0` 表示监听本机所有 IPv4 网卡，不是要写进网卡的地址。
4. 如果 Windows 询问网络访问权限，为这套接线所用网络允许本软件接收。不要同时运行占用 6001 的旧接收脚本。

地址与当前 A 工程 `td_project/import/ethernet_video_tx_top.v` 一致：FPGA `192.168.137.2:6002` → 电脑 `192.168.137.1:6001`。已正常工作的 HDMI/NPU 不需因使用上位机重新改 RTL、换参数或烧录。

如果来源地址不同，可以调整“限定FPGA来源”或暂时取消勾选；软件仍严格验证图像协议。有包但无完整图像时查看“异常包 / 不完整帧”。完全无数据时先检查网线、IP、FPGA网口发送和防火墙；软件没有虚构“已连接”状态。

## 图像与检测状态

- 新版视频是 FPGA 发出的 `640×360 RGB565 / UDP v3`，每帧360包，没有模型补黑。程序按 B 板相同的位扩展规则恢复 RGB888 供显示、保存，不进行平滑或增强；RGB565 丢弃的颜色低位无法恢复。
- 兼容旧版 `160×120 RGB888 / UDP v2` 和旧8字节包头，自动识别尺寸；仅旧视频含上下各15行模型补黑。
- 检测框 metadata 仍是160×120模型坐标。新版画面会去除15行补边，按4倍映射并裁剪到640×360；信息栏保留模型原坐标，JSON另存映射后的 `display_bbox`。
- “视频帧率”是收到完整网络视频帧的速率，**不是 NPU FPS**。
- “UDP视频帧号”是发送成功序号；“图像源帧号”是实际图像源 ID；“推理结果编号”每次发布结果递增。“结果源帧号”指出这份结果对应哪个输入。
- 同源有效框画绿色实线；最近一次有效历史框默认画橙色虚线，以便在视频速率高于NPU速率时仍能看到FPGA检测框。橙色框对应较早的输入，不能当成当前画面的同源结果；取消“显示历史框”可隐藏它。板端发布新的无效框结果后不再绘制旧框。
- “已发布结果：无有效人体框”表示 FPGA 发布了未满足画框条件的结果；“暂无已发布推理结果”表示还没有可关联的推理结果。
- UDP v2/v3 都没有 OBJ/PERSON 原始分数，软件明确显示“当前协议未发送分数”，不会拿视频帧率、框有效标志或 PC 预测冒充 FPGA 分数。

## 保存与排查无框

“保存当前原始帧”输出同名前缀的三个文件：

- `.rgb`：逐行RGB888，无上位机叠框。新版640×360为691200字节，旧版160×120为57600字节；新版文件是RGB565色彩重建后的像素。
- `.png`：同一份无损原始图像。
- `.json`：协议版本、视频帧号、源帧号、结果帧号、框坐标及接收时间。

“保存随后N张完整帧”可批量保存；它按上位机消费到的完整帧保存，不承诺网络帧序号连续。显示冻结不会停止接收和保存。默认保存至软件目录的 `captures` 子目录，可在界面选择其他位置。新版360包、旧版42包全部齐全，且包头长度和metadata一致时才发布完整帧；丢失/损坏帧不会补零伪造图像。

“用人体QAT模型分析当前帧”会先保存这张原始输入，再启动已有Python环境加载：

`C:\Users\lx292\Desktop\safety_grid_v1\runs\qat_person_v3\best_qat.pth`

默认解释器：`C:\Users\lx292\.conda\envs\yolo\python.exe`。可以在界面修改两个路径。它使用已保存激活scale与Person V3 QAT前向，选择OBJ最大网格，判断OBJ和PERSON是否均≥128；输出旁明确标为 **Python对照分数**。结果保存在同名 `.analysis.json`，不会修改模型或训练。

新版视频用于模型对照时，按0、4、8…的网络像素位置抽样到160×90，再上下各补15行黑边，与当前NPU采样相位一致。由于RGB565已经损失颜色低位，分数明确标为“近似对照”，不能当成与FPGA输入逐字节相同的结果。

PC图像预测和FPGA结果必须按源帧号核对；网络每帧可携带历史结果，不应把某张当前图像的Python结果直接与不同源的FPGA框比较。若结果源帧对应的原图未保存，需要多保存一些帧。对照可帮助判断模型是否能识别摄像头实际输入，不能代替读取FPGA原始分数。

## 协议与容错

当前v3：24字节包头、360包一帧；分包ID 0..359，每包1280图像字节（640个RGB565像素），UDP负载共1304字节。16位字段与RGB565像素均为大端。包头来自当前 A 工程的 `video_udp_tx.v` 与 `design_top_wrapper.v`，已用真实RTL发送数据验证。

兼容v2：24字节包头、42包一帧；前41包各1392图像字节，最后1包528字节，总图像57600字节。

|字节|内容|
|---|---|
|0..1 / 2..3 / 4..5|视频帧ID / 分包ID / 图像长度|
|6 / 7|首尾标记 / 新版03、兼容02|
|8..9 / 10|同步ID / bbox_valid|
|11..14 / 15|x1,y1,x2,y2 / 同步与框源有效标记|
|16..17 / 18..19 / 20..21|图像源ID / 结果源ID / 结果ID|
|22..23|保留0000|

兼容旧8字节包头（byte7=0），但旧协议没有框metadata。接收器容许同帧包乱序和相同内容重复包，按0.8秒超时丢弃不完整帧，最多保留4个未完成帧。数据互相冲突、非法包长或非法metadata不会作为完整图显示。帧号回绕可正常接收；板复位后若序号回退，出现接收间隔后自动恢复，也可停止后重新监听立即清除接收状态。界面“视频帧序号缺口”是序号统计，不等于物理链路精确丢包率。

## 自测与源码

源码运行：使用装有PyQt5的Python执行 `main.py`。`requirements.txt` 仅列出视频GUI依赖；可选模型分析还需现有模型工程及PyTorch。

本地演示（**非实板结果**）：`FPGA_Ethernet_Host.exe --demo`。它只向本机回环地址发送模拟图像，窗口与状态栏均会标注“本地模拟数据”。

测试入口：

```powershell
& "$env:USERPROFILE\.conda\envs\yolo\python.exe" -m unittest test_protocol test_gui -v
& "$env:USERPROFILE\.conda\envs\yolo\python.exe" -m unittest test_v3 -v
& "$env:USERPROFILE\.conda\envs\yolo\python.exe" validate_rtl_protocol.py
```

最后一项需要现有ModelSim，只运行RTL仿真，不进行综合、布局布线、FPGA位流或Flash操作。新版发布验证记录和截图在 `validation/udp_v3_20261023`。实时实板接收仍需接好网线后验证。
