# MG90S 独立舵机测试

日期：2026-10-06。用于排查外部 5 V 与 B 板共地后，舵机仍不动作的问题。

## 当前配置

用户此前已确认复位后每约两秒持续来回转动，独立自检通过。自动模式不动时发现共地线松脱；用户随后明确要求使用识别到火焰后按位置移动的模式。顶层默认值现为 `SERVO_TEST_MODE=0`（自动追踪与条件喷水），重新生成并烧录后生效。

以下描述适用于诊断时设置 `SERVO_TEST_MODE=1`、`SERVO_TEST_DWELL_MS=2000` 的情况。

- 测试信号直接使用板级 `I_sys_clk=50 MHz`，不依赖 HDMI PLL、NPU、检测框或测距结果。
- 同步释放测试复位，只依赖 `I_rst_n`；控制角度和 PWM 均属于该 50 MHz 域。
- 上电/复位释放后，先保持 90° 两秒，再循环 **60° → 90° → 120° → 90°**，每个位置两秒。
- PWM 周期 20 ms，1,000,000 个时钟；60°/90°/120°高电平分别为 58,333/75,000/91,667 个时钟，约 1.167/1.500/1.833 ms。
- 测试模式强制水泵处于关闭电平：默认高有效模块输出恒 0；配置低有效模块时输出恒 1。

新源文件：`td_project/import/servo_test_controller.v`，已注册到 `.al` 活动源清单。
新增单测与 PWM 联动测试位于 `simulation/fire_control`；原自动控制仍在 `SERVO_TEST_MODE=0` 分支。

验证结果：新增模块编译无错误、无警告；9 个仿真用例全部通过，包括真实 50 MHz 脉宽、角度循环、HDMI 时钟停止时的独立自检、水泵高/低有效关闭，以及原自动控制分支。全工程 ModelSim 编译仍有原 DDR 包装模块的 `dhi_clk` 诊断和 HDMI 加密 IP 警告，没有新增诊断；本次没有运行综合或 Bitgen。

补充自动模式验证：`tb_fire_control_real_clock.v` 使用真实 75 MHz 时钟计数和生产控制参数，41 项联动检查通过，编译/仿真无错误、无警告。实测左侧新检测把角度从 90° 调至 89°、高电平从 112,500 拍变为 111,667 拍；右侧新检测回到 90°，周期始终为 1,500,000 拍。与此前 9 项合计 10 个通过用例，仍不能代替实际共地和检测输入检查。

## 测试步骤

1. 断电，暂时卸下舵机机械负载，水泵电源保持断开。
2. 舵机红线接外部稳压 +5 V，棕线接其负极；负极同时接 B 板 J1.12、J1.30、J2.12 或 J2.30 任一 GND，均为同一块板上的公共地。用户这只舵机的黄色信号线接 J1.4 GPIOA_3/U1。按板上 1 脚标记定位排针，避免把“双排第 4 脚”理解为某一排的第四个位置。
3. 重新打开修改后的 **B 板** `.al` 工程，让新增测试源进入源列表。
4. 如需再次自检，先将顶层 `SERVO_TEST_MODE` 设为 `1'b1`，再重新综合、布局布线和 Bitgen，下载这次生成的配置文件。已下载的模式不会因为源码修改而改变。
5. 松开复位键，上电后等待至少 10 秒，观察是否按上述顺序动作。

如果新测试配置仍完全无动作，仍需核对实物排针、接头方向、外部电源是否实际供电、舵机本体及其控制输入电平兼容性，不能仅凭“没有声音”判定舵机损坏。没有仪表时，清晰的 J1 丝印/排针照片、舵机三线连接与电源照片可帮助进一步检查。

## 恢复自动控制

顶层 `SERVO_TEST_MODE` 当前为 `1'b0`。重新综合、布局布线、Bitgen 并下载新配置，即使用火焰追踪与条件喷水。没有新火焰检测结果时舵机不会按测试节奏循环；复位后回到 90°。诊断时设为 `1'b1` 才启用循环自检并强制水泵关闭。

开发与切换模式过程中，助手没有运行 Bitgen、下载配置或操控真实舵机；自检动作由用户实际烧录后确认。目录里的已有 bit 文件不随源码自动更新，切换模式后应重新生成并下载。
